# 前端审查问题修复设计

## 目标

修复前端代码审查发现的五项问题：查询错误响应导致崩溃、界面展示错误的提问、移动端无法导航、PDF 在大小校验前被读入内存，以及 lint 无法非交互运行。同时为关键行为增加自动化回归测试。

## 范围

- 修改 `apps/web/app/page.tsx` 的查询状态、错误处理和移动端导航。
- 修改 `apps/web/app/api/documents/upload/route.ts`，在读取或解析文件前执行 50 MB 限制。
- 增加少量可独立测试的前端/服务端辅助函数，避免测试依赖整个页面实现。
- 配置 ESLint CLI 和 Vitest，并增加针对本次缺陷的测试。
- 不重构现有演示数据、桌面布局或 RAG 后端，不引入完整端到端测试框架。

## 方案

### 查询处理

将 API 响应解析和结构校验放入独立辅助函数。只有同时包含合法 `status`、字符串 `answer` 和数组 `citations` 的成功响应才进入结果状态；非 2xx、无效 JSON 或结构错误统一转换为 `unavailable` 结果。输入框设置 `maxLength=4000`，提交时保存裁剪后的问题到独立的 `submittedQuestion` 状态，消息气泡显示该状态而不是硬编码示例。

### 移动端导航

保留桌面侧栏，在页面页头增加 `lg:hidden` 的移动导航。移动导航提供“问答”“文档”“解析”三个明确按钮，并以当前视图设置活动状态。详情页归属于文档区域，且原有返回按钮继续返回文档列表。

### 上传限制

在上传路由中定义 50 MB 上限，并在 `file.arrayBuffer()` 或 `processPdf()` 之前检查 `file.size`。超限时返回 HTTP 413 和稳定的中文错误信息。这个限制与 `.env.example` 和 Python RAG 服务当前的 `MAX_UPLOAD_MB=50` 保持一致。

### 工程检查

使用 ESLint CLI 取代会进入交互配置的 `next lint`。使用 Vitest 作为轻量测试运行器；测试覆盖查询响应规范化、实际提交问题的状态行为、移动导航的可达入口和上传大小限制。组件测试仅在需要验证交互时使用 React Testing Library，不引入 Playwright。

## 数据流与错误处理

1. 用户提交最多 4000 字的问题。
2. 页面保存本次提交文本并请求 `/api/query`。
3. 响应经过状态码和结构验证；异常转换为完整的 `unavailable` 结果，因此渲染层始终可以安全读取 `citations`。
4. 用户选择文件后，上传代理首先验证文件大小；超限文件不会被读取、解析或转发。
5. 合法文件继续沿用现有 PDF Inspector 与 RAG API 流程。

## 验证标准

- 422、500、无效 JSON或畸形查询响应不会使页面崩溃，并显示不可用提示。
- 提交任意问题后，消息气泡展示该问题，而非演示问题。
- 小于 `lg` 的视口中可以在三个一级页面之间导航。
- 超过 50 MB 的文件在 PDF 解析前返回 413。
- `npm test`、`npm run lint` 和 `npm run build` 均以非交互方式成功结束。
